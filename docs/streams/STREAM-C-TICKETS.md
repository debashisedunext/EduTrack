  - **Out-of-scope on either end is 404, and the far side of a link gets the same treatment as the ticket in the URL.** `ScopedTickets.byIds` — a new batch method — resolves every linked ticket's title/level/status through the caller's own row scope; a link to a ticket outside it is silently dropped from `linkedTickets` rather than rendered with a leaking reference. ⚠ **Touches Stream A's `api/security/scope/ScopedTickets.java`** (TEAM-PLAN.md §6) — `ScopeGuardRulesTest` forbids reaching `TicketRepository` from outside that package, so there was no way to build this inside `feature/tickets/links/` instead. Flagged for Shivendra's sign-off, C-020's precedent on `PermissionMatrix.java`.
  - **`ticket.update_progress`, all six roles, both verbs.** Noting a relationship is supporting work on a ticket, the same shape as a comment or an attachment, not a directing decision like assign/priority/close/reopen — those are the three-role rows. Unlinking needs no "uploader, or a PM" row rule the way attachment deletion does: `ticket_links` is ordinary mutable data, not one of CLAUDE.md's three append-only tables, so either side of a relationship may remove it, and the service still writes who did. Permission-matrix entries added for both routes, `PermissionMatrixTest` and `RouteAuthorizationTest` green.
  - Each create and each delete writes its own `ticket_history` row (`TICKET_LINKED`/`TICKET_UNLINKED`) on the ticket the caller acted from, worded exactly as they submitted it — `BLOCKED_BY CRM-26-00312` for a caller who picked "Is blocked by" — even on the canonicalised direction. What happened is what the caller asked for; the storage direction is this service's business, not the audit trail's.
  - ⚠ **Also Stream D — `frontend/src/mocks/`.** Two new handlers plus `linkedTickets` on the `/full` mock, mirroring the real service's canonicalisation and scoping exactly (`canonicalizeLink`, `inverseLinkType` in `handlers/tickets.ts`) — without them `mock coverage > every contract operation has a handler` fails the moment the client regenerates, and `TicketLinksControl` has nothing to develop against under `npm run dev`. Flagged rather than done quietly, C-015/C-019's precedent in this same file.
  - The "Linked" row carries no `canChangeLevel`-style gate on a sealed earlier cycle: unlike Level, a link is not cycle-scoped at all (`ticket_links` has no `cycle_no`), so there is no "which cycle" question for a past cycle's read-only view to raise.
  - Target ticket picked from a debounced search (`GET /tickets?q=`), not `SearchableDropdown` — that component filters a pre-fetched `options` array client-side, and the ticket corpus is far too large to fetch whole. The path ticket is filtered out of its own search results client-side; the server refuses a self-link either way.
  - ⚠ **The dropped `Idempotency-Key`.** `createTicketLink` is a `201`-returning create and CONVENTIONS.md §4 asks every one for the header, but orval drops header parameters — the same gap C-010 found on `useCreateTicket`.
